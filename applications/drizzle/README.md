# @supschema/drizzle

Creates [Drizzle ORM](https://orm.drizzle.team) tables, relations and enums from SupSchema models at runtime. Column types are fully inferred, so `$inferSelect`, `$inferInsert` and typed queries work as with hand-written Drizzle schemas.

Supported dialects: `postgresql`, `mysql`, `sqlite`.

```bash
npm install @supschema/common-types @supschema/model-types @supschema/drizzle drizzle-orm
npm install -D drizzle-kit
```

## 1. Describe models

The dialect is chosen once by importing its entry point: `@supschema/drizzle/postgresql`, `@supschema/drizzle/mysql` or `@supschema/drizzle/sqlite`. Import it in the models file, so `.$drizzle()` and `drizzleTable` are available and typed for that dialect everywhere.

```typescript
// src/models.ts
import '@supschema/drizzle/postgresql';
import { S } from '@supschema/common-types';
import { Model, ModelRelation, Unique } from '@supschema/model-types';

export const UserStatus = S.Enum({ active: {}, blocked: {} });

export const User = Model(
  {
    name: 'User',
    key: ['id'],
    // Without `name` the default name of drizzle is used, e.g. `User_name_index`
    indexes: [{ fields: ['name'] }, { fields: ['status'], name: 'user_status_idx' }],
  },
  {
    id: S.Int32(),
    // `maxLength` is validated by the application only, the column is `text` (`varchar(255)` in MySQL)
    email: Unique(S.String({ maxLength: 255 })),
    name: S.String(),
    status: UserStatus,
    bio: S.Nullable(S.String()),
    // Objects and arrays of non-scalar values are stored as JSON
    settings: S.Object({ theme: S.Enum({ dark: {}, light: {} }), notifications: S.Boolean() }),
  },
);

export const Post = Model(
  { name: 'Post', key: ['id'] },
  { id: S.Int32(), authorId: S.Int32(), title: S.String(), tags: S.Array(S.String()) },
);

export const PostAuthor = ModelRelation(Post, 'author', ['authorId'], User, 'posts', ['id'], { onDelete: 'Cascade' });
```

## 2. Generate the schema file

drizzle-kit reads tables and enums from the exports of a schema file. Instead of writing this file by hand, generate it with a small script. Keys of the passed record are module paths relative to the generated file:

```typescript
// scripts/generate-db-schema.ts
import { writeDrizzleSchemaFile } from '@supschema/drizzle';
import { UserStatus, User, Post, PostAuthor } from '../src/models.js';

// The dialect is taken from the imported entry point, `path` defaults to `schema.gen.ts`
await writeDrizzleSchemaFile(
  { path: 'src/db/schema.gen.ts' },
  { '../models.js': { UserStatus, User, Post, PostAuthor } },
);
```

The generated file only re-exports the result of `drizzleSchema`, so it has to be regenerated only when models are added, removed or renamed. Changes of model properties are picked up at runtime.

```typescript
// src/db/schema.gen.ts
// This file is generated by @supschema/drizzle. Do not edit it manually.
import { drizzleSchema } from "@supschema/drizzle/postgresql";
import * as schemas from "../models.js";

export const {
  UserStatus,
  User,
  Post,
  UserRelations,
  PostRelations,
} = drizzleSchema({
  UserStatus: schemas.UserStatus,
  User: schemas.User,
  Post: schemas.Post,
  PostAuthor: schemas.PostAuthor,
});
```

## 3. Use it with drizzle-kit and Drizzle ORM

```typescript
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit';

export default defineConfig({
  dialect: 'postgresql',
  schema: './src/db/schema.gen.ts',
  out: './drizzle',
  dbCredentials: { url: process.env.DATABASE_URL! },
});
```

```typescript
// src/app.ts
import { drizzle } from 'drizzle-orm/node-postgres';
import { eq } from 'drizzle-orm';
import * as schema from './db/schema.gen.js';

const db = drizzle(process.env.DATABASE_URL!, { schema });

// { id: number; email: string; name: string; status: 'active' | 'blocked'; bio: string | null;
//   settings: { theme: 'dark' | 'light'; notifications: boolean } }
type User = typeof schema.User.$inferSelect;

await db.insert(schema.User).values({
  id: 1,
  email: 'ann@example.com',
  name: 'Ann',
  status: 'active',
  settings: { theme: 'dark', notifications: true },
});

const [ann] = await db.select().from(schema.User).where(eq(schema.User.email, 'ann@example.com'));
const posts = await db.query.Post.findMany({ with: { author: true } });
```

## Drizzle specific settings

Everything not described by the model itself can be added with Drizzle builders of the chosen dialect.

### Columns

`.$drizzle()` modifies the column builder, e.g. to add defaults, identity, `$defaultFn`, `$onUpdate` or `references`. The callback receives the builder of the dialect, and the returned type is used in the table type, so a column with a default becomes optional in `$inferInsert`. Calls can be chained. `.notNull()`, `.primaryKey()` and `.unique()` are added by the table afterwards.

```typescript
import { sql } from 'drizzle-orm';

export const Post = Model(
  { name: 'Post', key: ['id'] },
  {
    id: S.Int32().$drizzle((c) => c.generatedAlwaysAsIdentity()),
    title: S.String(),
    views: S.Int32().$drizzle((c) => c.default(0)),
    createdAt: S.Int64()
      .$drizzle((c) => c.default(sql`extract(epoch from now())::bigint`))
      .$drizzle((c) => c.$onUpdate(() => sql`extract(epoch from now())::bigint`)),
    // Modifiers are kept when the schema is wrapped or modified
    subtitle: S.Nullable(S.String().$drizzle((c) => c.default(''))),
  },
);
```

Other column types are set with `.$drizzle()` as well, the table adds the column name:

```typescript
import { varchar } from 'drizzle-orm/pg-core';

code: S.String().$drizzle(() => varchar({ length: 10 })),
```

The modifier is stored as schema metadata, not as an option. So it is not serialized, it is kept by `Unique`, `modifyOpts` and other metadata set with `withSchemaMeta` from `@supschema/core`, regardless of the order.

### Tables

The model option `drizzleTable` adds indexes, checks, policies and other extra config to the ones generated from `key`, `uniques`, `indexes` and relations. `t` contains the columns of the model.

```typescript
import { sql } from 'drizzle-orm';
import { check, index } from 'drizzle-orm/pg-core';

export const Post = Model(
  {
    name: 'Post',
    key: ['id'],
    drizzleTable: {
      extraConfig: (t) => [
        index('Post_tags_gin_idx').using('gin', t.tags),
        check('Post_views_check', sql`${t.views} >= 0`),
      ],
    },
  },
  { id: S.Int32(), views: S.Int32(), tags: S.Array(S.String()) },
);
```

If several dialect entry points are imported in one TypeScript program, the builders are typed as a union of the dialects. The dialect can then be set explicitly:

```typescript
declare module '@supschema/drizzle' {
  interface DrizzleConfig {
    dialect: 'postgresql';
  }
}
```

## Custom types

A schema type gets a column with `columnDef`. Dialects can be omitted, using the type with an omitted dialect throws an `UnsupportedDialectError`:

```typescript
import { createType, extend } from '@supschema/core';
import { S } from '@supschema/common-types';
import { columnDef } from '@supschema/drizzle';
import { customType } from 'drizzle-orm/pg-core';

const citext = customType<{ data: string }>({ dataType: () => 'citext' });

export const Email = createType<S.String>(import.meta, S.String);
extend(Email, {
  get $drizzleColumn() {
    return columnDef(this, { postgresql: () => citext() });
  },
} as never);
```

## Using `drizzleSchema` directly

Without drizzle-kit, e.g. in tests, the schema can be created directly:

```typescript
import { drizzleSchema } from '@supschema/drizzle/postgresql';

const { User, Post, PostRelations } = drizzleSchema({ User, Post, PostAuthor });
```

Result keys:

| Key                   | Value                                                              |
| --------------------- | ------------------------------------------------------------------ |
| `<Model>`             | Table                                                              |
| `<Model>Relations`    | Relations for the relational query API                             |
| `<Enum>`              | PostgreSQL enum (only for `postgresql`)                            |
| `<Model><Property>`   | PostgreSQL enum of a property, if the enum is not passed explicitly |
| `<name>Schema`        | Database schema of models and enums with `dbSchema` option         |
